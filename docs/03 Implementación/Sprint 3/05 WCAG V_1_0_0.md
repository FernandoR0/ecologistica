Evaluación de las 8 pantallas frente a **WCAG 2.1 nivel AA** con:

- **Lighthouse 12.6.1** en la pantalla de inicio de sesión (móvil y escritorio).
- **axe-core 4.10** con las reglas `wcag2a`, `wcag2aa`, `wcag21a` y `wcag21aa`, ejecutado dentro de las pruebas E2E
  (`e2e/test_e2e.py`) en cada pantalla con la sesión iniciada.
- Revisión manual con teclado (Tab, Shift+Tab, Enter) en Chrome.

## 2. Hallazgos Principales y Correcciones

Las auditorías automáticas no encontraron violaciones. Estas son las decisiones de diseño que lo permitieron y los
puntos que se revisaron a mano:

| Criterio de Conformidad | Problema que se previno o revisó | Componente Afectado | Solución Aplicada |
|---|---|---|---|
| 1.1.1 Contenido no textual | Un mapa sin texto alternativo no se entiende con lector de pantalla | `MapaRutas.tsx` | `role="region"` con `aria-label="Mapa de rutas"`; cada parada tiene un popup con cliente, código y hora, y la misma información se lista debajo del mapa |
| 1.4.3 Contraste mínimo | Textos secundarios grises podían quedar bajo 4.5:1 | `styles.css` | Gris `#5b6472` sobre el fondo `#f6f7f4` (5.56:1) y verde `#0f766e` en botones con texto blanco |
| 2.4.7 Foco visible | El foco por defecto se pierde sobre el fondo verde del menú | Botones, enlaces y campos | `:focus-visible` con contorno ámbar `#f59e0b` de 3 px |
| 3.3.1 Identificación de errores | Un error de validación de la API (422) llegaba como texto técnico | `api.ts`, `CrudPage.tsx` | `mensajeError()` convierte el error en «campo: mensaje» y se muestra con `role="alert"` |
| 4.1.3 Mensajes de estado | El resultado de generar rutas no se anunciaba | `Rutas.tsx` | Resumen del plan con `role="status"` |
| 1.4.10 Reflow | En celular el menú lateral tapaba el contenido | `Layout.tsx`, `styles.css` | Desde 760 px el menú pasa a una fila superior |
