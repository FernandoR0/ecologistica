# Índice de documentación - EcoLogística - Optimizador de rutas sostenibles de última milla

Recorre la documentación en este orden. Cada documento lleva versión `V_x_y_z` en el nombre;
al modificarlo, sube la versión y registra el cambio en `04 Seguimiento y Control/02 Control de cambios`.

| Fase | Carpeta | Contenido |
|---|---|---|
| 1. Inicio | `01 Inicio/` | Enfoque, acta, visión, supuestos, interesados, requisitos, usuarios, reglas, stack, BD, C4, restricciones |
| 2. Planificación | `02 Planificación/` | Transformación ágil, artefactos Jira, riesgos, presupuesto, cronograma |
| 3. Implementación | `03 Implementación/Sprint N/` | Informe de estado, impedimentos, revisión y retrospectiva de cada sprint |
| | `03 Implementación/Sprint 3/` | + Calidad de código (SonarQube), OWASP, WCAG |
| | `03 Implementación/reduccion del impacto ambiental/` | Informe de impacto ambiental y estándares de ingeniería de software |
| 4. Seguimiento y Control | `04 Seguimiento y Control/` | Informe de seguimiento, control de cambios, riesgos, métricas |
| 5. Cierre | `05 Cierre/` | Acta de cierre, informe final, lecciones aprendidas, acta de aceptación |
| Anexos | `06 Anexos/` | Pruebas, usabilidad SUS, manual de usuario, defectos, incidentes, informe técnico |

> Los campos `_Completar_` se deben llenar con datos reales del equipo (fechas, nombres, evidencias, capturas).
> No inventes métricas: ejecuta las pruebas y pega los resultados reales.
