## 2. Justificación Técnica Formal

**Declaración:** EcoLogística se construye con **Python 3.12 + FastAPI** en el backend, **Google OR-Tools** (Búsqueda
Tabú) como motor de optimización, **PostgreSQL 16** con **SQLAlchemy 2** como persistencia y **React 19 + Vite +
TypeScript** con **Leaflet/OpenStreetMap** en el frontend, empaquetados en **Docker** y automatizados con **GitHub
Actions**.

| Criterio de decisión | Sustento |
|---|---|
| Ajuste al problema | El núcleo del proyecto es el VRPTW con criterio de emisiones. OR-Tools resuelve VRPTW con dimensiones de capacidad, tiempo y descansos y trae la metaheurística Búsqueda Tabú lista y probada; con MERN habría que implementarla desde cero, con mayor riesgo para RNF-001 (≤ 45 s). |
| Escalabilidad | La API FastAPI es sin estado (sesión en JWT), por lo que escala horizontalmente agregando réplicas detrás de un balanceador (RNF-009); PostgreSQL soporta 1 000 pedidos diarios con índices en `estado`, `fecha` y llaves foráneas. |
| Perfil del equipo | El desarrollador conoce Python y TypeScript; la curva media es asumible en el semestre, a diferencia de Spring Boot + Angular. |
| Bajo consumo energético en la nube | FastAPI consume menos memoria que la JVM, la imagen `python:3.12-slim` es pequeña y el cálculo pesado corre en C++ dentro de OR-Tools. El frontend se compila y se sirve estático, comprimido con Brotli y con caché de larga duración. |
| Costo | Todas las piezas son de código abierto; la infraestructura usa planes gratuitos o de bajo costo (presupuesto OPEX de USD 184). |
| Calidad y seguridad | FastAPI valida toda entrada con Pydantic (mitiga inyección), SQLAlchemy parametriza las consultas y OpenAPI documenta la API automáticamente (RNF-007 del caso). |
